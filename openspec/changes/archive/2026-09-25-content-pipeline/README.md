## Rules checklist

Dated yes for each of the twelve constraint beads (`bd list -l constraint --all`), against what this change builds: the `Content` package, the card and string-family data, the content test, the literal lint, and the two catalogue-key edits to the skeleton's `TodayView.swift` and `NewEntryView.swift`.

- mm-pr1, The never list — yes, 25 September 2026. No card or string names calories, macros, portions, a goal weight, a BMI, a streak, a badge, a score, or a food photo; none compares the person to other people.
- mm-pr2, Tone of every string — yes, 25 September 2026, as a Draft. Every card is matter-of-fact, states a lapse as a lapse, and holds no cheer or medical language; `ToneTests` checks what a machine can check, and the clinical reviewer signs off the rest before release.
- mm-pr3, Vocabulary — yes, 25 September 2026. No string holds "log", "meal log", "food diary", "intake", "portion", "serving", "calories", "tracker" or "user"; "binge" appears only in "binge eating", "binge eat" or "a binge" in every card (`ToneTests.testShippedCardsUseBingeOnlyInTheAllowedPhrases`).
- mm-pr4, Nothing looks like a nutrition app — yes, 25 September 2026. No card holds an image reference; the content test fails one that does (`CardCountTests`).
- mm-pr5, The product name and the plan slot — yes, 25 September 2026. "Midmorning" appears with no hyphen in `exclusion.age` and `exclusion.treatment`; this change writes no plan-slot string.
- mm-pr6, What a notification never shows — not applicable to this change. `content-pipeline` builds no notification; `reminders` (2.4) owns that requirement.
- mm-pr7, The person can put it down — not applicable to this change. `content-pipeline` builds no switch or "Pause for today" control; `settings` (1.3) and `weekly-review` (3.2) own those.
- mm-pr8, Accessibility everywhere — yes, 25 September 2026, for what this change builds. `CardScreen.voiceOverHeadings` names the title and "One thing to do"; the screen keeps a long card's full text with no truncation (`CardScreenTests`). The literal lint keeps every accessibility label in a catalogue. The rendered view and its device check wait for `mm-t21.23`.
- mm-pr9, Dates and times in strings — not applicable. No string this change bundles holds a date, a time or a duration; every count enters through `%lld`, never the device locale.
- mm-pr10, Offline and private by default — yes, 25 September 2026. The bundle loader reads only local files under `Resources`; nothing in `Content` makes a network call (`BundledCardsTests.testTheBundleLoadsFromLocalFilesOnly`).
- mm-pr11, No AI at runtime — yes, 25 September 2026. Every card and string is bundled, hand-written data; the `Content` package calls no language model and holds no generative code path.
- mm-pr12, Appearance — yes, 25 September 2026. `Content` holds no view or colour. The two skeleton-view edits replace a literal with a catalogue key and change no colour, font or layout.

**Get support on every screen.** This change adds no full screen. `CardScreen` is a value type the Programme screen (`mm-t21.23`) renders later; the requirement applies once that view exists.
